# Phase 1 可行性门：Kuikly + API 22 手表（Go/No-Go）

> **来源计划**：`/home/rj/.claude/plans/ethereal-sniffing-popcorn.md` 阶段 1「Kuikly + API 22 手表可行性门（Go/No-Go）」
> **本文件作用**：把可行性门的验收流程固化，供真实 HarmonyOS NEXT 6.1 / API 22 手表到位后照此执行、记录并裁决。
> **当前状态**：本环境无真机、无 DevEco Studio，门 **保持 OPEN**，待硬件与工具链到位后按本文件执行。

---

## 1. 目标

在真实 HarmonyOS 6.1 / API 22 圆形手表上验证 Kuikly 共享页面方案的 7 项关键能力，并依据 Go 条件做出 Go/No-Go 裁决：

- **Go** → 采用 Kuikly 共享页面，继续投入 Kuikly renderer。
- **No-Go** → 保留 `shared/core` 与 platform ports，Harmony UI 转 ArkUI/ArkTS，停止投资 Kuikly renderer，但不回滚已抽取的 Kotlin 核心。

本门只裁决「Kuikly/API 22 真机可行性」，不裁决整体架构；阶段 1 之前锁定的工具链版本见第 7 节。

## 3. 7 项能力验收清单

通用约定：

- 每项给出 **验证步骤**、**通过标准**、**需记录的测量指标**。
- 关键指标须与**第 5 节预算表**对照，超预算即记为不通过（除非另有裁决）。
- 全部原始数据（截图、`hdc` 输出、Profiler 报告、抓包文件、日志）作为 evidence 归档。

### 3.1 HAP 安装、Kuikly 页面启动、前后台/重建、异常恢复

**验证步骤**
- [ ] 通过 DevEco/hdc 安装签名 HAP，记录安装耗时与首次启动耗时
- [ ] 冷启动 Kuikly 页面，记录到首帧的时间（启动分析）
- [ ] 热启动 / 从后台恢复，观察状态是否保持
- [ ] 循环切换前台↔后台（≥ 50 次），期间杀进程后重建
- [ ] 注入异常：进程被杀（`hdc shell kill` / 低内存回收）、OOM 边界、Activity/Ability 重建
- [ ] 验证崩溃/恢复路径：无闪退循环、无黑屏、可回到前序状态

**通过标准**
- HAP 安装成功率 100%；Kuikly 页面可冷/热启动
- 前后台往返不丢 UI 状态、不闪退；重建后导航栈/滚动位置/播放状态可恢复
- 异常后可在合理时间内自动或手动恢复，无崩溃循环

**需记录的测量指标**
- 安装耗时（s）、冷启动到首帧耗时（ms）、热启动耗时（ms）
- 前后台往返成功率、重建恢复成功率、恢复耗时（ms）
- 异常注入后的崩溃次数、恢复时间、最终状态正确性

### 3.2 圆屏裁切、安全区、表冠滚动、点击/滑动/返回、字体缩放

**验证步骤**
- [ ] 在圆形表盘四角放置测试控件，检查是否被圆屏裁切
- [ ] 读取安全区 API 返回值并核对四边 inset 应用结果（顶部状态栏、底部手势区、侧边圆角）
- [ ] 表冠滚动驱动列表/弹幕/进度条，验证滚动增量映射
- [ ] 点击、滑动、返回手势（含侧滑返回）在关键页面全量走查
- [ ] 系统字体缩放到 1.0 / 1.25 / 1.5 档，逐页检查文字截断与布局溢出

**通过标准**
- 无关键控件被圆屏裁切；安全区 inset 正确应用
- 表冠滚动可用且方向/灵敏度合理；点击/滑动/返回三者在验收页 100% 可用
- 字体缩放各档位下无文字截断、无布局溢出、无不响应

**需记录的测量指标**
- 被裁切控件数、安全区 inset 测量值（px）
- 表冠滚动映射线性度/灵敏度数据、手势成功率
- 各缩放档位下的布局溢出数、截断文本数

### 3.3 ArkTS/N-API/Kotlin 跨线程调用、回调、取消、内存释放

**验证步骤**
- [ ] ArkTS 侧调用 N-API 导出函数（业务 DTO/命令/事件），验证往返
- [ ] 在非 UI 线程执行网络/磁盘任务，UI 线程不被阻塞
- [ ] 回调路径：异步任务完成后回调到 ArkTS/Kuikly，测量到达率与延迟
- [ ] 取消语义：任务取消后无悬空回调、无崩溃、资源（句柄/内存）释放
- [ ] 长时间压力测试（≥ 30 分钟反复调用）后检查内存曲线是否收敛
- [ ] 通过内存快照对比确认无泄漏

**通过标准**
- 跨线程调用/回调往返延迟达预算；UI 线程无阻塞卡顿
- 取消后无悬空回调、无内存/句柄泄漏；压力测试下 RSS 稳定不单调上涨

**需记录的测量指标**
- 单次调用往返延迟（ms）、回调到达率（%）、回调延迟（ms）
- 取消后的资源回收时间、压力测试内存曲线（峰值/稳态，MB）
- 泄漏检查结果（快照对比差异，MB）

### 3.4 带 Cookie/Referer/UA 的 HTTPS、重定向、WBI 签名、扫码登录、刷新登录

**验证步骤**
- [ ] 对同一 fixture，与 Android 基线对比请求头（UA/Referer/Cookie）逐项一致
- [ ] 抓包验证 HTTPS 请求头实际到达服务端的值（抓包工具/服务端回显）
- [ ] 重定向链：跟随、跨域、降级场景各测一轮，记录跳转次数与耗时
- [ ] 对同一 fixture 运行 WBI 签名，与 Android 基线输出**逐字节一致**（golden test）
- [ ] 扫码登录全流程：扫码→授权→回调→写 Cookie→进入登录态
- [ ] 刷新登录：Cookie 过期/401 后刷新，验证续期且不丢登录态

**通过标准**
- 请求头与服务端所见与 Android 基线一致；带 Cookie/Referer/UA 可访问需鉴权接口
- 重定向正确跟随，无错误重定向或死循环
- WBI/AppSign 与 Android 基线逐字节一致（fixture 驱动）
- 扫码登录、刷新登录完整可用；401/过期路径处理正确

**需记录的测量指标**
- 头部一致性比对结果（逐项/逐字节）、重定向跳转次数与耗时（ms）
- WBI golden 比对通过率（%）
- 扫码登录成功率、刷新登录成功率、掉登录次数

### 3.5 实际 B 站 MP4、分离 DASH 音视频、直播播放；seek/倍速/切集/403 刷新 URL

**验证步骤**
- [ ] 用真实 B 站视频源分别验证 MP4、分离 DASH 音视频、直播三类播放
- [ ] 记录每类源的起播延迟（点击到画面出现）
- [ ] seek 前后跳跃，测量精度与延迟；验证音画同步
- [ ] 倍速 0.5x / 1.0x / 1.5x / 2.0x 各档位验证
- [ ] 播放中切集（连续播放下一集/切换视频），验证无崩溃
- [ ] 构造 403（URL 过期/签名失效）后触发刷新 URL，验证续播成功

**通过标准**
- MP4 / 分离 DASH / 直播三类在 API 22 真机全部可播放
- seek 精度与延迟达预算；音画同步偏差在预算内
- 倍速可用、切集无崩溃；403 后刷新 URL 并成功续播

**需记录的测量指标**
- 起播延迟（ms）、首帧时间（ms）、seek 延迟/精度（ms）、音画同步偏差（ms）
- 倍速各档可用性、切集耗时（ms）、403 刷新成功率与恢复时间（ms）

### 3.6 视频 Surface/XComponent 上叠加 Kuikly UI 与弹幕：z-order、触摸、帧率、内存、温升

**验证步骤**
- [ ] 视频 Surface/XComponent 与 Kuikly UI、弹幕三者叠层，验证 z-order 正确
- [ ] 触摸事件：UI 控件/弹幕层命中正确，不穿透到视频、不误触
- [ ] 用 Profiler 对比「裸播放」与「叠加 UI+弹幕」的帧率
- [ ] 记录叠加场景的峰值内存与 30 分钟连续播放的温升曲线
- [ ] 密集弹幕 + 播放同开时检查卡顿/ANR

**通过标准**
- 三叠层 z-order 正确、触摸命中正确；视频画面不被 UI 遮挡导致功能不可用
- 叠加场景帧率不低于预算（相对裸播放下降在允许范围）
- 峰值内存、温升在预算内；无 ANR/卡顿

**需记录的测量指标**
- z-order 正确性检查结果、触摸命中正确率
- 叠加后帧率（fps）与相对下降、峰值内存（MB）、温升（℃/时间曲线）
- 长播期间 ANR/卡顿次数

### 3.7 后台续播、音频焦点、通知/控制中心、沙盒下载、Range 续传、重启恢复

**验证步骤**
- [ ] 切后台/息屏后续播，验证音频不中断
- [ ] 音频焦点抢占（来电/其他 App 播放）时暂停/恢复正确
- [ ] 通知与控制中心：播放/暂停/seek/切集指令可用
- [ ] 沙盒内发起下载任务，验证写入应用沙盒
- [ ] 断点续传：中途中断后按 Range 续传，校验字节一致性（如 MD5）
- [ ] 进程/设备重启后：下载任务状态与播放状态可恢复

**通过标准**
- 后台续播、音频焦点抢占/恢复行为正确；控制中心指令响应正常
- 沙盒下载可用；Range 续传字节一致；重启后任务与状态可恢复

**需记录的测量指标**
- 后台续播时长、焦点切换响应时间（ms）、控制中心指令延迟（ms）
- 下载成功率、断点续传字节校验结果、重启恢复成功率

## 4. Go 条件（照计划）

以下 **4 条全部满足** 才可判 Go；任一条不满足即触发 No-Go 评审：

1. **能力稳定**：第 3 节 7 项能力在 API 22 真机上全部达到各自通过标准，且通过回归复测（≥ 2 轮）。
2. **工具链 CI 可重建**：DevEco/Harmony SDK API 22/Hvigor/NDK/Kuikly/Kotlin fork/JDK/宿主 OS 版本锁定，可在 CI 或干净环境复建 HAP 与 `.so`，制品可审计（SBOM、源码提供义务、许可证清单）。
3. **性能/功耗达预算**：第 5 节预算表各项达标（含校准后的最终预算值）。
4. **无不可审计私有制品**：未依赖无法审计或无法长期取得的私有制品；所有依赖可获取、可复建、许可证合规。

## 6. 决策日志格式

每次执行（完整验收或单项复测）追加一条记录，作为裁决依据。字段固定为：

| date | device build | toolchain commit | result | evidence |
|------|--------------|------------------|--------|----------|
| `YYYY-MM-DD` | 设备型号 + 系统版本/构建号 | DevEco/SDK/Hvigor/Kuikly/Kotlin fork 的版本与 commit（可用清单/哈希） | Go / No-Go / 单项结果（通过项、未通过项及原因） | 报告/日志/抓包/截图/Profiler 输出归档路径或 commit |

模板：

```markdown
| 2026-XX-XX | HUAWEI WATCH XXX / HarmonyOS NEXT 6.1.0 (XXX) | dev-eco: X.X.X, sdk-api22: X.X.X, hvigor: X.X.X, kuikly: <commit>, kotlin-fork: <commit> | 7 项全部通过 / 第 X 项未通过：<原因> | `docs/feasibility-gate/2026-XX-XX/`（含 hdc 日志、Profiler 报告、抓包、截图） |
```

裁决规则：所有 Go 条件满足 → **Go**；任一关键条件不满足 → 触发 **No-Go 评审**，评审结论与理由同样按上述格式记录。
